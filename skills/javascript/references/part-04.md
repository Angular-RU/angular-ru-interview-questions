### JavaScript interview questions



#### Вопрос: Что такое event delegation?

**Короткий ответ**

Event delegation — это прием, при котором обработчик события ставят на общего родителя, а не на каждый дочерний элемент.
Событие всплывает вверх по DOM, а обработчик определяет исходный элемент через event.target. Это уменьшает число
listeners и удобно для динамических списков; в Angular template bindings обычно скрывают детали, но понимание DOM events
помогает писать directives и интеграции.

**Полный ответ**

Event delegation — это прием, при котором обработчик события ставят на общего родителя, а не на каждый дочерний элемент.
Событие всплывает вверх по DOM, а обработчик определяет исходный элемент через `event.target`. Это уменьшает число
listeners и удобно для динамических списков; в Angular template bindings обычно скрывают детали, но понимание DOM events
помогает писать directives и интеграции.

```js
list.addEventListener('click', (event) => {
  const button = event.target.closest('button[data-id]');

  if (!button || !list.contains(button)) {
    return;
  }

  selectItem(button.dataset.id);
});
```

#### Вопрос: Что такое hoisting?

**Короткий ответ**

Hoisting — поведение, при котором declarations обрабатываются до выполнения кода в scope. Function declarations доступны
до объявления, var создается со значением undefined, а let, const и class находятся в temporal dead zone до строки
объявления. Поэтому порядок кода все равно важен для читаемости и корректности.

#### Вопрос: Что такое event bubbling?

delegation. Обработчик должен проверять event.target, event.currentTarget и границы контейнера, чтобы не обработать
чужой элемент.

delegation. Обработчик должен проверять `event.target`, `event.currentTarget` и границы контейнера, чтобы не обработать

#### Вопрос: Что такое event capturing?

где порядок bubbling недостаточен.

#### Вопрос: Как arrow function меняет поведение this?

**Короткий ответ**

Arrow function не имеет собственного this, arguments и prototype; она лексически берет this из внешней области. Это
удобно для callbacks, где нужно сохранить context, но плохо подходит для prototype methods и constructors. В class
fields arrow methods создаются на instance, а не на prototype.

**Полный ответ**

Arrow function не имеет собственного `this`, `arguments` и `prototype`; она лексически берет `this` из внешней области.
Это удобно для callbacks, где нужно сохранить context, но плохо подходит для prototype methods и constructors. В class
fields arrow methods создаются на instance, а не на prototype.

#### Вопрос: Почему == может быть опасен?

**Короткий ответ**

== сравнивает значения после неявного преобразования типов, что дает неожиданные результаты вроде '' == 0 и false == 0.
=== сравнивает без такого приведения и обычно безопаснее. Исключения должны быть осознанными и локальными, например

Если foo — массив, каждый push добавляет элемент в конец и увеличивает length на 1. Метод возвращает новую длину
массива. Например, после const foo = []; foo.push(1); foo.push(2); значение foo.length будет 2.

**Полный ответ**

Если `foo` — массив, каждый `push` добавляет элемент в конец и увеличивает `length` на 1. Метод возвращает новую длину

#### Вопрос: Что произойдет в выражении foo.x = foo = {n: 2}?

**Короткий ответ**

Левая ссылка foo.x вычисляется до переназначения foo. Затем foo начинает указывать на новый объект {n: 2}, а свойство x
записывается в старый объект, на который foo больше не указывает. Пример проверяет порядок вычисления assignment
expressions и отличие ссылки на объект от переменной.

**Полный ответ**

Левая ссылка `foo.x` вычисляется до переназначения `foo`. Затем `foo` начинает указывать на новый объект `{n: 2}`, а
свойство `x` записывается в старый объект, на который `foo` больше не указывает. Пример проверяет порядок вычисления
assignment expressions и отличие ссылки на объект от переменной.





#### Вопрос: В каком порядке выведутся console.log, setTimeout и Promise.then?

**Короткий ответ**

Порядок: one, four, three, two. Сначала выполняется синхронный код, затем microtask из Promise.then, затем macrotask из
setTimeout.

**Полный ответ**

```js
console.log('one');

setTimeout(() => {
  console.log('two');
}, 0);

Promise.resolve().then(() => {
  console.log('three');
});

console.log('four');
```

Порядок: `one`, `four`, `three`, `two`. Сначала выполняется синхронный код, затем microtask из `Promise.then`, затем
macrotask из `setTimeout`.





#### Вопрос: Чем отличаются promise chain с return, без return, с вызовом функции и с передачей функции?

**Короткий ответ**

Если then возвращает Promise или значение, следующий шаг ждет и получает этот результат. Если return забыли, следующий
then продолжится с undefined и не дождется вложенной async-операции. then(doWork) передает функцию для будущего вызова,
а then(doWork()) вызывает ее сразу и передает результат.

**Полный ответ**

Если `then` возвращает Promise или значение, следующий шаг ждет и получает этот результат. Если `return` забыли,
следующий `then` продолжится с `undefined` и не дождется вложенной async-операции. `then(doWork)` передает функцию для
будущего вызова, а `then(doWork())` вызывает ее сразу и передает результат.

#### Вопрос: Почему return и объект на следующей строке могут сломаться из-за ASI?

**Короткий ответ**

Automatic Semicolon Insertion вставит semicolon после return, если expression начинается на следующей строке. Функция
вернет undefined, а object literal станет отдельным недостижимым блоком. Объект нужно писать на той же строке или
оборачивать перенос правильно.

**Полный ответ**

Automatic Semicolon Insertion вставит semicolon после `return`, если expression начинается на следующей строке. Функция
вернет `undefined`, а object literal станет отдельным недостижимым блоком. Объект нужно писать на той же строке или
оборачивать перенос правильно.

```js
function getUser() {
  return {
    name: 'Max',
  };
}
```





#### Вопрос: Реализуйте duplicate([1, 2, 3]), чтобы получить [1, 2, 3, 1, 2, 3].

**Короткий ответ**

Это shallow copy: вложенные объекты не клонируются, а остаются теми же ссылками.

**Полный ответ**

```js
function duplicate(items) {
  return [...items, ...items];
}
```

Это shallow copy: вложенные объекты не клонируются, а остаются теми же ссылками.

#### Вопрос: Что вернут выражения 'hello' || 'world' и 'foo' && 'bar'?

**Короткий ответ**

'hello' || 'world' вернет 'hello', потому что || возвращает первое truthy значение. 'foo' && 'bar' вернет 'bar', потому
что && возвращает первое falsy значение или последний operand, если все truthy. Эти операторы возвращают исходные
значения, а не обязательно boolean.

**Полный ответ**

`'bar'`, потому что `&&` возвращает первое falsy значение или последний operand, если все truthy. Эти операторы
возвращают исходные значения, а не обязательно boolean.





#### Вопрос: Напишите IIFE и объясните, зачем она раньше использовалась.

**Короткий ответ**

IIFE выполняется сразу и создает отдельную scope для локальных переменных. До ES modules ее часто использовали, чтобы не
загрязнять global scope и скрывать implementation details.

**Полный ответ**

```js
(function () {
  const localValue = 'hidden';

  window.appName = 'Demo';
})();
```

IIFE выполняется сразу и создает отдельную scope для локальных переменных. До ES modules ее часто использовали, чтобы не
загрязнять global scope и скрывать implementation details.
